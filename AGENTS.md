# AGENTS.md

Shared rules for every AI agent working in this repository (Claude Code and Gemini). Tool-specific instructions live in `CLAUDE.md` (Claude Code) and `GEMINI.md` (Gemini). Edit this file for anything that applies to both.

## Purpose

Study material for the 2nd year of the BSc in Aerospace Engineering at UC3M: an Obsidian vault, a static HTML study portal, and the official course material they are built from. Two goals, in order:
1. Theory explained in full detail for each topic, faithful to the official sources.
2. Every problem of each topic solved one by one, step by step, with no algebraic skips.

## Architecture

Content flows in one direction; each layer must agree with the one before it:

```
sources/cuatrimestre-1/   (official course material, ground truth)
  └─► vault/              (Obsidian notes)
        └─► subjects/     (static HTML pages)
              └─► index.html  (portal landing page)
```

Subject folder names differ per tree, by design (see `sources/README.md` for the source layout):

| Subject | `sources/cuatrimestre-1/` | `vault/` | `subjects/` |
| :--- | :--- | :--- | :--- |
| Fluid Mechanics | `01-fluid-mechanics/` | `01 - Fluid Mechanics/` | `fluid-mechanics/` |
| Aerospace Materials I | `02-aerospace-materials-1/` | `02 - Aerospace Materials I/` | `aerospace-materials-1/` |
| Engineering Mechanics | `03-engineering-mechanics/` | `03 - Engineering Mechanics/` | `engineering-mechanics/` |
| Advanced Maths | `04-advanced-maths/` | `04 - Advanced Maths/` | `advanced-maths/` |
| Business Management | `05-business-management/` | `05 - Business Management/` | `business-management/` |

- **`sources/cuatrimestre-1/<NN-subject>/`**: official course material, organised by unit (`unit-0N-*/`) and by type (`teoria/`, `slides/`, `problemas/`, `examenes/`, `laboratorios/`, `schedule/`). Never invent equations, data, or problem statements; extract them and cite document and page/slide. `sources/update_inventory.py` and `.ps1` regenerate the inventory.
- **`vault/`**: Obsidian vault (open `vault/` itself). Subject folders as above, a `00 - Indice Central` MOC (update it when adding notes), `Templates/` (concept, exam problem, formula summary) and `attachments/`. Notes need YAML frontmatter and `[[wikilinks]]`. Wikilinks with a folder prefix must use the vault folder names from the table.
- **`subjects/<subject>/{teoria,problemas,sources,exams}/`**: `teoria/` and `problemas/` hold one `index.html` plus `topic-N-*.html` pages; `sources/index.html` ("Theory & exercise PDFs": theory, slides and problem sheets by unit) and `exams/index.html` ("Exams": first, second, third partial and final, newest year first) are generated by `python tools/build_sources_pages.py` (never edit them by hand). Exams are classified from their file names, `SUBJECT_KIND_YEAR[_DETAILS].pdf` with KIND one of `FIRSTPARTIAL`, `SECONDPARTIAL`, `THIRDPARTIAL`, `FINALEXAM` and details such as `ORD`, `EXTRA`, `RETAKE`, `SOL`, `P1`, `G45`, `MT3`; name new exam files that way. Exams from other universities or degrees use KIND `OTHERUNI` (`SUBJECT_OTHERUNI_YEAR_INSTITUTION[_DETAILS]`), live in `examenes/other-universities/`, and are listed in their own section. The index badges for both pages and the hero's PDF total are audited (`badge-drift`). Copy the structure of a sibling page rather than starting from scratch. **Laboratory material is never published on the web**: there are no lab pages, links, or lab entries in `assets/data/sources.js`; lab files stay in `sources/` only.
- **`assets/`**: shared portal assets: `css/celestial-sky.css`, `css/study-surface.css` (flat, opaque reading background for subject pages), `css/tokens.css` (design tokens), `css/hub.css` (root `index.html` only), `js/celestial-sky.js` (animated sky, root `index.html` only), `js/theme.js`, `js/i18n.js`, `js/quotes.js`, `css/source-links.css` (style of the PDF deep links), `css/responsive.css` (phone-width safety net), `js/ask-ai.js` + `css/ask-ai.css` (Ask AI), `js/focus-lab.js` + `css/focus-lab.css` (Focus Lab study sound), `js/pdf-export.js` + `css/print.css` (PDF buttons and A4 print layout), `pdf/` (generated PDFs), and `data/sources.js` (generated by `tools/sources_manifest.py`; do not edit by hand).
- **`tools/`**: quality gates, see Verification below.

### Mandatory pipeline: Obsidian first, web second

1. Extracted content (course PDFs, notes, problems) is structured in `vault/` first, using `vault/Templates/`, and linked from the subject MOC.
2. Only then is the web page written in `subjects/`, using the vault note as ground truth. No web page exists without its vault note.

## Language and units

- All study material, vault notes, solved problems, and portal pages are written in **English**. Repo docs and some folder names are Spanish.
- SI units throughout; include a dimensional check.

## Web page rules

- Back-link to the portal is `../../../index.html` (pages are three levels deep).
- KaTeX via CDN; math delimiters `$...$` inline and `$$...$$` for blocks.
- Typography matches the existing pages: Newsreader for body text, Abril Fatface for display headings, JetBrains Mono for code. Load them from Google Fonts.
- Background: the animated sky (`<canvas id="celestial-canvas">` + `assets/js/celestial-sky.js`) is for the root `index.html` only. Subject pages load `assets/css/study-surface.css` right after `celestial-sky.css` for a flat, matte background and opaque cards, and carry no canvas or `celestial-sky.js`.
- Dark/light theme: load `assets/js/theme.js` in `<head>` and include a `#themeToggle` button. The script owns the single storage key `ae_theme`; pages must not carry their own inline theme code or write any other theme key (`audit_portal` fails on it). `assets/js/i18n.js` keeps its own language key, which is not a theme key.
- Reading palettes: `assets/js/theme.js` also owns `<html data-surface>` (`default`, `cream`, `sepia`, `slate-paper`, `sage`, `charcoal`), stored under the key `ae_surface` (never a key containing "theme"), and builds the swatch picker in front of `#themeToggle` on every page that loads `study-surface.css` (the generated `sources/` and `exams/` pages load it too, from `tools/build_sources_pages.py`); pages carry no picker markup and no extra script. The palettes are CSS in `assets/css/study-surface.css` (sections 5 to 11, screen only: the PDF layout sets `data-theme="print"` and ignores them), each bound to one polarity (light palettes set `data-theme="light"`, `charcoal` sets `"dark"`; a theme toggle that breaks the pairing resets the surface to `default`). They re-point the `--study-*` variables and the pages' own text/background/border variables, so new pages need nothing beyond the usual `study-surface.css` link. Every text colour must stay AAA (7:1; large text 4.5:1) on every palette. Subject accents, SVG label fills, the Ask AI widget, raster figures and the quote card are handled by lightness-window rules in sections 7 to 11; when a new page brings accent-coloured text under a class that is not listed in section 7, add the selector there (`tools/tests/test_surface.py` loads real pages under every palette, fails on any text below AAA and on any change of a page's own text). Palettes only restyle: never edit a page's content to fit one.
- Responsive: usable on phone, tablet, and desktop. Every `teoria/` and `problemas/` topic page links `assets/css/responsive.css` as the last stylesheet in `<head>` (header wrapping, scrolling tables, KaTeX's hidden MathML kept inside scroll boxes; `audit_portal` fails on `missing-responsive`). Put wide tables in a `.table-wrapper` or `.table-container`.
- **No interactive simulators** (Canvas, Three.js). Static, readable study pages only.
- Focus Lab: `assets/js/theme.js` loads `assets/js/focus-lab.js` on every page (no page carries its own tag, so adding it changed no page and no PDF). It adds a floating "Focus" button and a non-modal panel that synthesises study sound with the Web Audio API (binaural beats with strict stereo panning, an isochronic mode for speakers, looped brown/pink noise, ramped gains so nothing clicks), with five presets, a live mixer and a small `AnalyserNode` visualiser (its only `<canvas>`: a site-wide tool, not a study-page simulator). No audio files; settings persist under `ae_focus_lab`. It is skipped in the PDF print mode and hidden in print. Text colours come from the reading palette (`--study-text`, `--study-text-2`), never from the subject accent. Tests: `tools/tests/test_focus_lab.py`.
- "Ask AI": every `teoria/` and `problemas/` topic page loads `<script defer src="../../../assets/js/ask-ai.js"></script>` right after `theme.js` (`audit_portal` fails on `missing-ask-ai`). Selecting text shows an "Ask AI" pill; on problem pages each card also gets a bar under its statement (Socratic tutor, full explanation of the solution, statement only, check my attempt, similar exercise). The panel builds a structured prompt (role, context, material with formulas as LaTeX, task, answer rules) and opens Claude (prefilled link) or Gemini (prompt copied, then pasted). It never calls an API or stores keys; its styles (`assets/css/ask-ai.css`) use each page's own colour and font variables. Problem cards are split into statement and solution by `splitCard` in the script; keep statements in `.problem-statement-box`, `.statement-box` or `.problem-statement` and solutions in phase blocks so the split stays right.
- PDFs: every `teoria/` and `problemas/` topic page loads `<script defer src="../../../assets/js/pdf-export.js"></script>` after `ask-ai.js` (`audit_portal` fails on `missing-pdf-export`). It adds "Download PDF" / "Open as PDF" under the title (all problems together on problem pages) and on every problem card, linking to A4 PDFs in `assets/pdf/<subject>/<area>/<page>.pdf` and `<page>/<card id>.pdf`. They are printed by `python tools/build_pdfs.py` with the black-and-white layout of `assets/css/print.css` (the same layout the browser's own print uses); after editing a topic page, run it (it reprints only the PDFs whose page changed; `--katex DIR` uses a local KaTeX when the CDN is unreachable). Never edit `assets/pdf/` by hand.
- Theory pages listed in `tools/topic_pages.json` are generated from their vault note by `python tools/build_topic_pages.py`: edit the vault note (and, for drawings, the figure module in `tools/figures/`), then run the tool; never edit those pages by hand. Figures are embedded in the note as `![[attachments/<folder>/<name>.svg]]`.
- Business Management: the three theory pages (`subjects/business-management/teoria/topic-{1,2,3}.html`) are generated from `vault/05 - Business Management/Topic N - ....md`, which follow the official decks slide by slide and contain only material from `sources/`. The two Topic 3 problem pages are generated by `python tools/build_problem_pages.py` from the vault notes `Problem - T3 Exercise N ...` and `Problem - T3 Extra N ...` (four phases plus a final `Check against the official key` section built from `T3_Financial Statements_SOLUTIONS.pdf` and `T3_Additional_SOLUTIONS.pdf`; edit the note, never the page), and the exam-type page opens with `Concept - Method to Build the Income Statement and Balance Sheet`. After any change to a Business page, run in this order: `python tools/build_topic_pages.py` (theory), `python tools/build_problem_pages.py` (problems), `python tools/source_links.py`, then `python tools/build_pdfs.py`, or the matching `--check` fails. Where the CDN or Google Fonts are blocked (e.g. cloud sessions), print with `--katex DIR` and local copies of the fonts so the PDFs keep the portal typography.
- Deep links to the official PDFs: every problem card has an "Original statement" link to the page of the PDF where its statement starts, each topic page has an "Official material" strip, and inline citations (`[Slide 14]`, `Notes.pdf, Eq. 2.26`, `Robinson, Sec. 7.6, p. 54`, `[Session 4 Slide 22]`) link to that page of the PDF. They are generated by `python tools/source_links.py` from `tools/source_links.json`; never write or edit them by hand. When you add a page or a problem card, add it to the JSON and run the tool (`--refresh-anchors` re-reads equation and section labels from the PDFs and needs `pdftotext`). Citation text inside `$...$` is never linked, so keep citations outside math.
- Each subject's card on root `index.html` shows badges that must match the pages on disk ("N of M units", "N problems"). Problem pages mark each problem with a `problem-card` element so the count can be audited. Unbuilt areas are shown as `aria-disabled`, not as dead links.

## Problem-solving standard

Worked problems follow four phases:

1. **Setup:** formal statement, hypotheses, degrees of freedom, constraints, parameter table with SI units. Explain why each equation or principle is used, and what it buys over alternatives, before stating it.
2. **Frames:** define the coordinate systems and bases involved; build the change-of-basis matrix (e.g. $[{}_0 R_1]$) and check $\det R = 1$, $R R^T = I$.
3. **Derivation:** cite the exact source for each result (e.g. "Notes Eq. 2.6", "Slide 29", "Robinson Eq. 5.12"). Show every step with no algebraic skips:
   - chain rule explicitly, e.g. $\frac{d}{dt}f(u(t)) = \frac{df}{du}\frac{du}{dt}$; product rule $\frac{d}{dt}(uv) = \dot{u}v + u\dot{v}$ and implicit differentiation where they apply;
   - for each integral: the antiderivative, the substitution with its differential $du = u'(t)\,dt$, and the limits substituted via Barrow's rule $[F]_{t_1}^{t_2} = F(t_2) - F(t_1)$.
   - Never jump straight from a derivative or integral to its result.
4. **Interpretation:** physical meaning, limiting cases, asymptotic behaviour, dimensional verification in SI.

### Content integrity

- Never adjust data, rounding, or an intermediate step to match an official answer. If the computed result differs from the official key, keep the computed value and add a discrepancy callout (`> [!warning] Discrepancy with the official solution` in the vault, a note box on the web page).
- If the official solution itself is wrong, show the correction as an erratum with the check that proves it; mark readings of handwriting or figures as such.
- Mark anything beyond the course material as "extension"; do not present it as course content.
- Vault note names are English: `Concept - ...`, `Problem - ...`, `Topic N - ...`, `Formula Sheet - ...`, `<Subject> MOC`. Rename notes with `python tools/vault_rename.py map.json --apply`, which rewrites every wikilink.
- Do not write `\euro` (undefined in KaTeX); use `€` inside `\text{}`.

## Review protocols

### `review` (standard task gate, after any single problem, note, page, or fix)
1. KaTeX delimiters balanced (`$...$`, `$$...$$`), no raw LaTeX errors.
2. Back-links point to `../../../index.html`.
3. Content is 100% academic English.
4. YAML frontmatter complete in `vault/` notes.
5. Subject MOC and root `index.html` entries updated; no stray scratch files left in the repo.

### `ultrareview` (chapter, problem sheet, exam, or on request)
Run the `review-ultrareview` skill, which checks four dimensions:
1. **Algebra and calculus:** zero algebraic skips; every chain rule, differential, and Barrow substitution explicit (`problem-step-mentor`).
2. **Frames and dimensions:** $[{}_0 R_1]$ orthonormal; every term dimensionally homogeneous in SI.
3. **Sources:** strict verification against the official PDFs in `sources/` (`source-researcher`).
4. **Web and memory:** theme persistence (`localStorage('ae_theme')` via `assets/js/theme.js`), responsive layout, zero JS console errors, `render_check` clean (`web-qa-reviewer`).

Run the auditors read-only and in separate contexts (math, theory against sources, web and hygiene); fix findings only after re-verifying each one independently.

## Token economy and memory

1. **Prompt cache stability:** keep system instructions, agent definitions, and skill frontmatter static; do not inject timestamps or volatile metadata into prompt prefixes.
2. **Context shielding:** never dump source PDFs, logs, or directory trees into the chat. Use targeted reads, `ctx_search`, or sandboxed `ctx_execute` to extract only what is needed.
3. **Memory persistence (`claude-mem`):** record resolved questions, verified formulas, and established frames as short summaries (<100 tokens) so future sessions can recover them cheaply.
4. **Concise responses:** when files are created or changed on disk, do not repeat their contents in chat. Give a clickable link, a summary of the diff, and the key rationale.

## Verification tools

From the repository root (pure-stdlib Python 3, no installs):
- `python tools/vault_lint.py` lints `vault/` (`--fix` applies safe fixes).
- `python tools/audit_portal.py` gates `index.html` and `subjects/**/*.html`.
- `python tools/sources_manifest.py --check` fails if `assets/data/sources.js` is stale; `python tools/build_sources_pages.py --check` does the same for the `subjects/<slug>/sources/index.html` pages (run without `--check` to regenerate).
- `python tools/build_topic_pages.py --check` fails if a generated theory page or its figures no longer match the vault note.
- `python tools/build_problem_pages.py --check` fails if a Business Management Topic 3 problem page no longer matches its vault notes.
- `python tools/source_links.py --check` fails if any page's PDF deep links are stale; `audit_portal` also fails on a problem card without its "Original statement" link (`missing-source-link`).
- `python tools/build_pdfs.py --check` fails if a PDF in `assets/pdf/` is missing, stale or orphaned (no browser needed; run without `--check` to print them, which needs Edge/Chrome).
- `python tools/render_check.py <pages>` (or `--all`) renders pages in headless Edge/Chrome with the real KaTeX and fails on any KaTeX error or leftover `$$`. `audit_portal`'s delimiter check does not catch undefined macros; this does.
- `python tools/vault_rename.py map.json [--apply]` renames vault notes and rewrites wikilinks (dry run by default).
- `python -m unittest discover -s tools/tests` runs the test suite.

A task is closed only when `vault_lint` and `audit_portal` report 0 errors, `render_check` is clean on every page you edited, the PDFs are rebuilt (`build_pdfs --check`), and the tests pass.

## Git

- The `web_qa_reviewer` role manages version control: `git status`, `git add`, `git commit` with a descriptive message, and `git push` to `origin/main`, as part of closing a task.
- Other agents do not commit or push unless the user asks.
- Commit messages: `type(scope): summary` (e.g. `feat(fluids): ...`, `chore(maths): ...`).
- The working tree may contain unrelated uncommitted changes. Stage only the files relevant to the task.
- The vault is committed to Git so every team member shares the same notes. Obsidian workspace and cache files, and `graphify-out/`, are gitignored.
