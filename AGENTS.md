# AGENTS.md

Shared rules for every AI agent working in this repository (Claude Code and Gemini). Tool-specific instructions live in `CLAUDE.md` (Claude Code) and `GEMINI.md` (Gemini). Edit this file for anything that applies to both.

## Purpose

Study material for the 2nd year of the BSc in Aerospace Engineering at UC3M: an Obsidian vault, a static HTML study portal, and the official course material they are built from. Two goals, in order:
1. Theory explained in full detail for each topic, faithful to the official sources.
2. Every problem of each topic solved one by one, step by step, with no algebraic skips.

## Architecture

Content flows in one direction; each layer must agree with the one before it:

```
sources/cuatrimestre-1/   (official course material, ground truth)
  └─► vault/              (Obsidian notes)
        └─► subjects/     (static HTML pages)
              └─► index.html  (portal landing page)
```

Subject folder names differ per tree, by design (see `sources/README.md` for the source layout):

| Subject | `sources/cuatrimestre-1/` | `vault/` | `subjects/` |
| :--- | :--- | :--- | :--- |
| Fluid Mechanics | `01-fluid-mechanics/` | `01 - Fluid Mechanics/` | `fluid-mechanics/` |
| Aerospace Materials I | `02-aerospace-materials-1/` | `02 - Aerospace Materials I/` | `aerospace-materials-1/` |
| Engineering Mechanics | `03-engineering-mechanics/` | `03 - Engineering Mechanics/` | `engineering-mechanics/` |
| Advanced Maths | `04-advanced-maths/` | `04 - Advanced Maths/` | `advanced-maths/` |
| Business Management | `05-business-management/` | `05 - Business Management/` | `business-management/` |

- **`sources/cuatrimestre-1/<NN-subject>/`**: official course material, organised by unit (`unit-0N-*/`) and by type (`teoria/`, `slides/`, `problemas/`, `examenes/`, `laboratorios/`, `schedule/`). Never invent equations, data, or problem statements; extract them and cite document and page/slide. `sources/update_inventory.py` and `.ps1` regenerate the inventory.
- **`vault/`**: Obsidian vault (open `vault/` itself). Subject folders as above, a `00 - Indice Central` MOC (update it when adding notes), `Templates/` (concept, exam problem, formula summary), `attachments/`, `06 - Repository/` (notes on the tools, agents and rules of this repo) and `07 - Sources/` (one generated note per file under `sources/`, with its status and the notes that reference it; generated by `tools/build_source_notes.py`, never edited by hand). Notes need YAML frontmatter and `[[wikilinks]]`. Wikilinks with a folder prefix must use the vault folder names from the table.
- **`subjects/<subject>/{teoria,problemas,sources,exams}/`**: `teoria/` and `problemas/` hold one `index.html` plus `topic-N-*.html` pages; `sources/index.html` ("PDFs": the PDF library, with theory, slides and problem sheets by unit followed by the past exams by exam, newest year first, and a search box and filters by type, unit, exam and year added by `assets/js/pdf-library.js`) and `exams/index.html` ("Solved exams": a "Coming soon" placeholder that links to the exam PDFs of the library and will hold the solved exams; it lists no PDF) are generated by `python tools/build_sources_pages.py` (never edit them by hand). Both copy the tab strip and header icon of the subject's `teoria/index.html` and are styled by `assets/css/pdf-library.css`. Exams are classified from their file names, `SUBJECT_KIND_YEAR[_DETAILS].pdf` with KIND one of `FIRSTPARTIAL`, `SECONDPARTIAL`, `THIRDPARTIAL`, `FINALEXAM` and details such as `ORD`, `EXTRA`, `RETAKE`, `SOL`, `P1`, `G45`, `MT3`; name new exam files that way. Exams from other universities or degrees use KIND `OTHERUNI` (`SUBJECT_OTHERUNI_YEAR_INSTITUTION[_DETAILS]`), live in `examenes/other-universities/`, and are listed in their own section. The PDFs badge of each subject on the landing page counts every file of the library, exams included, and is audited (`badge-drift`); the Exams entry carries no count. Copy the structure of a sibling page rather than starting from scratch. **Laboratory material is never published on the web**: there are no lab pages, links, or lab entries in `assets/data/sources.js`; lab files stay in `sources/` only.
- **`assets/`**: shared portal assets: `css/celestial-sky.css`, `css/study-surface.css` (flat, opaque reading background for subject pages), `css/tokens.css` (design tokens), `css/hub.css` (root `index.html` only), `js/celestial-sky.js` (animated sky, root `index.html` only), `js/theme.js`, `js/i18n.js`, `js/quotes.js`, `css/source-links.css` (style of the PDF deep links), `css/responsive.css` (phone-width safety net), `js/ask-ai.js` + `css/ask-ai.css` (Ask AI), `js/focus-lab.js` + `css/focus-lab.css` (Focus Lab study sound), `js/pomodoro.js` + `css/pomodoro.css` (study timer and session planner), `js/updates.js` + `css/updates.css` ("What's new" bell and panel), `js/sidebar.js` + `css/sidebar.css` (side menu), `js/pdf-export.js` + `css/print.css` (PDF buttons and A4 print layout), `pdf/` (generated PDFs), and `data/sources.js` (generated by `tools/sources_manifest.py`; do not edit by hand).
- **`tools/`**: quality gates, see Verification below.

### Mandatory pipeline: Obsidian first, web second

1. Extracted content (course PDFs, notes, problems) is structured in `vault/` first, using `vault/Templates/`, and linked from the subject MOC.
2. Only then is the web page written in `subjects/`, using the vault note as ground truth. No web page exists without its vault note.

## Language and units

- All study material, vault notes, solved problems, and portal pages are written in **English**. Repo docs and some folder names are Spanish.
- SI units throughout; include a dimensional check.

## Web page rules

- Back-link to the portal is `../../../index.html` (pages are three levels deep). It is the only navigation link a page carries in its header: moving between subjects, areas, topics and sections is the job of the side menu (below), so a `teoria/` or `problemas/` page has no "Theory Index", "Problems" or "Topic N" buttons in the header and no bar of jump pills (`pill-nav-bar`, `subchapter-nav-bar`, `pills-bar`, `quick-jump`, `quick-nav`). The previous/next links at the end of an article and the buttons inside the index pages' own content stay. `tools/tests/test_sidebar.py` fails on a page that brings them back.
- KaTeX via CDN; math delimiters `$...$` inline and `$$...$$` for blocks.
- Typography matches the existing pages: Newsreader for body text, Abril Fatface for display headings, JetBrains Mono for code. Load them from Google Fonts.
- Background: the animated sky (`<canvas id="celestial-canvas">` + `assets/js/celestial-sky.js`) is for the root `index.html` only. Subject pages load `assets/css/study-surface.css` right after `celestial-sky.css` for a flat, matte background and opaque cards, and carry no canvas or `celestial-sky.js`.
- Dark/light theme: load `assets/js/theme.js` in `<head>` and include a `#themeToggle` button. The script owns the single storage key `ae_theme`; pages must not carry their own inline theme code or write any other theme key (`audit_portal` fails on it). `assets/js/i18n.js` keeps its own language key, which is not a theme key. On subject pages the script hides `#themeToggle` (the reading palettes own the polarity); on the root `index.html`, which has no palettes, the button switches dark and light. The script also adds the favicon (`assets/img/favicon.svg`) to every page that does not link one; only the root `index.html` links it itself.
- Reading palettes: `assets/js/theme.js` also owns `<html data-surface>` (`default`, `cream`, `sepia`, `slate-paper`, `sage`, `charcoal`), stored under the key `ae_surface` (never a key containing "theme"), and builds the swatch picker in front of `#themeToggle` on every page that loads `study-surface.css` (the generated `sources/` and `exams/` pages load it too, from `tools/build_sources_pages.py`); pages carry no picker markup and no extra script. The palettes are CSS in `assets/css/study-surface.css` (sections 5 to 11, screen only: the PDF layout sets `data-theme="print"` and ignores them), each bound to one polarity (light palettes set `data-theme="light"`, `charcoal` sets `"dark"`; a theme toggle that breaks the pairing resets the surface to `default`). They re-point the `--study-*` variables and the pages' own text/background/border variables, so new pages need nothing beyond the usual `study-surface.css` link. Every text colour must stay AAA (7:1; large text 4.5:1) on every palette. Under Charcoal the raster figures keep their real colours on a light mat, dimmed (section 10), because inverting them lost every light detail; under any dark theme the crimson force vectors of the Engineering Mechanics figures (`#be123c`) take a lighter rose (section 8). Subject accents, SVG label fills, the Ask AI widget, raster figures and the quote card are handled by lightness-window rules in sections 7 to 11; when a new page brings accent-coloured text under a class that is not listed in section 7, add the selector there (`tools/tests/test_surface.py` loads real pages under every palette, fails on any text below AAA and on any change of a page's own text). Palettes only restyle: never edit a page's content to fit one.
- Subject index pages: every `teoria/`, `problemas/` and `extra-problems/` `index.html` links `assets/css/subject-index.css` as its last stylesheet. It lays the page's own cards out as a compact grid (number, title, arrow) and hides the long summaries, tag clouds and the second copy of the tab strip, so a syllabus fits on one desktop screen; it also paints the starry sky behind the page, slowly drifting (tiles `assets/img/sky/<subject>-<dark|light>.svg` and two faint nebulae in the subject colours, on the body's own colour so every reading palette keeps its background; the page header is transparent, cards stay opaque); text colours stay the page's own. On desktop (a card group at least 900 px wide) `assets/js/subject-orbits.js` (+ `assets/css/subject-orbits.css`, loaded by `theme.js`, which acts only on these index pages) draws each group of cards as a solar system: a star in the centre, a dotted elliptical orbit and every card as a numbered planet with its title, placed clockwise from the upper left in DOM order (links, classes and counts unchanged); narrower screens keep the card grid. No storage; reduced motion stops the star and the orbit; skipped in the PDF print mode. Tests: `tools/tests/test_subject_orbits.py`. The header icon of these pages is the subject icon of the landing page. The site name is "Sideris". It is written once, as `SITE_NAME` in `assets/js/theme.js`, which sets the browser-tab title at run time: "Sideris" on the landing page and "Sideris Fluids", "Sideris Materials", "Sideris Mechanics", "Sideris Maths" or "Sideris Management" on every page of a subject (`SUBJECT_SHORT`, keyed by the folder under `subjects/`), and fills any `[data-site-name]` element. Pages keep their own descriptive `<title>` in the file (used by the PDF print mode and by search engines), so renaming the site never reprints a PDF; do not write the site name into page titles by hand.
- Responsive: usable on phone, tablet, and desktop. Every `teoria/` and `problemas/` topic page links `assets/css/responsive.css` as the last stylesheet in `<head>` (header wrapping, scrolling tables, KaTeX's hidden MathML kept inside scroll boxes; `audit_portal` fails on `missing-responsive`). Put wide tables in a `.table-wrapper` or `.table-container`.
- **Figures from the official PDFs (Screenshot-First, every subject).** A figure that reproduces something printed in the official material of `sources/` (diagram, graph, sketch, photograph, micrograph, table drawn as an image, the figure of a problem statement) is a PNG crop of that PDF page, never a redrawn SVG: rendered at 200 DPI with `pymupdf` (`page.get_pixmap(dpi=200, clip=fitz.Rect(...))`), white background, no slide title, header, footer or page number, saved in `vault/attachments/<folder>/` and registered with `REG.raster(name, title, caption, width)` (`tools/figures/svgkit.py`) in the topic's figure module; its caption names the source (`Copied from Session 21 Slide 3`, `Notes.pdf, Fig. 6.1`, `Problems.pdf, p. 4`). Every crop is opened and inspected before it is used (cut-off labels, fragments of the next figure or illegible text are re-cropped, never embedded). A generated SVG (`REG.put`) is kept only in two cases: **EXTRA**, the drawing exists in no official PDF and is a teaching aid or a step of a solution (deduction figures of Engineering Mechanics, free-body diagrams, a curve plotted from a table, the answer to "draw this diagram", overlays such as tie lines on a cropped diagram); **INVIABLE**, the crop is impossible or reads worse than a drawing (handwriting over the figure, an illegible scan, a figure missing from the PDF), stated in a comment next to the `REG.put` call. A value read off a figure is marked "reading of the figure". Aerospace Materials I (Topics 1 to 11), Business Management (Topics 1 to 7), Fluid Mechanics (Topics 3 to 7) and Engineering Mechanics (theory Topics 6 to 8) follow this rule (migration log: `docs/plans/2026-11-19-screenshot-first-migration.md`); the Advanced Maths phase portraits are computed answers, EXTRA by this rule, since its problem sheets print no figure. Some subject sections below still describe figures as "redrawn" from before the migration.
- **Exercise simulators (SVG only).** A worked problem may carry an interactive geometry simulator, placed **inside its own problem card** (never on a page of its own, never on a theory page): inline SVG redrawn by a shared script, with range sliders and selects, no `<canvas>`, no WebGL or Three.js and no storage. The default state reproduces the data of the statement; the readouts are computed with the formulas of that solution; the controls are hidden in print, so the PDF shows the default view. Text colours come from the page variables so every reading palette stays AAA. Fluid Mechanics Topic 5 is the first user (`assets/js/hydrostatics-sim.js` + `assets/css/hydrostatics-sim.css`, see below). Engineering Mechanics has its own engine, `assets/js/mechanics-3d-sim.js` + `assets/css/mechanics-3d-sim.css`: one double view (`viewBox="0 0 760 360"`: an orbitable axonometric view on the left; on the right the plane normal to the active rotation axis folded down, with ⊙/⊗, the angle, the right triangle and the live matrix $[{}_0 R_1]$) and eight declarative archetypes (`curvilinear-3d`, `rotating-wire-groove`, `oscillator-phase`, `rb-euler-kinematics`, `rb-inertia-principal`, `rb-planar-dynamics`, `rb-rolling-contact`, `rb-gyro-multibody`). A problem connects to it with the frontmatter key `sim: {archetype, params, defaults, readouts}` of its note, which the builder turns into `<div class="m3-sim" data-archetype data-config>`; `readouts` are the formulas of that solution, evaluated by the script's arithmetic parser (no `eval`). Its text takes the page's text variables only (registered in section 8 of `study-surface.css`). Tests: `tools/tests/test_mechanics_sim.py` (harness `mechanics_sim_harness.html`). Everything else stays a static, readable study page.

## Problem-solving standard

A worked problem reads as one continuous academic development that follows the order, methods and notation of the lecturer of its subject. No problem, extra problem, vault note, template, page or PDF shows "Phase 1", "First phase", "Phase 2", ..., "four phases" or "4-phase" as a heading, badge, label or sentence. (The internal CSS class `phase-block` stays: it is never shown, and `ask-ai.js`, `solution-close.js` and `print.css` rely on it.)

### Internal verification checklist (silent)

Agents run this checklist in their head on every solution before it is written and when they review one. It is never written into the solution:

1. Hypotheses, degrees of freedom, constraints and data with SI units are stated, and the reason for each principle is given before it is used.
2. Every frame and basis is defined; every change-of-basis matrix (e.g. $[{}_0 R_1]$) is checked ($\det R = 1$, $R R^T = I$).
3. The derivation has no algebraic skips and cites its source for each result ("Notes Eq. 2.6", "Slide 29", "Robinson Eq. 5.12"):
   - chain rule explicitly, e.g. $\frac{d}{dt}f(u(t)) = \frac{df}{du}\frac{du}{dt}$; product rule $\frac{d}{dt}(uv) = \dot{u}v + u\dot{v}$ and implicit differentiation where they apply;
   - for each integral: the antiderivative, the substitution with its differential $du = u'(t)\,dt$, and the limits substituted via Barrow's rule $[F]_{t_1}^{t_2} = F(t_2) - F(t_1)$;
   - never jump straight from a derivative or integral to its result.
4. Physical meaning, limiting cases, asymptotic behaviour and the SI dimensional check are present.

### Visible structure: the lecturer's order, per subject

| :--- | :--- |
| Engineering Mechanics | **Reference frames, bases and coordinates** (fixed frame $S_0$, moving frames $S_1, \dots$, bases $B_0, B_1$, intrinsic basis $\{\mathbf e_t, \mathbf e_n, \mathbf e_b\}$, degrees of freedom, constraints, parameter table) → **Change of basis and position vector** (geometric and trigonometric deduction of every basis change and of the position vector, built step by step, e.g. $\mathbf r_1^P = \overrightarrow{OC} + \overrightarrow{CP}$, with its figures) → **Kinematics** (velocities and accelerations: chain rule, product rule, angular velocities, composition of motions and Coriolis) → **Forces and equations of motion** (free-body diagram, applied and constraint forces and inertia forces projected in the chosen basis, equations of motion; left out when the problem has no dynamics) → **Answers and checks** (the explicit answer to every part of the statement, limiting cases such as $\theta = 0$ or $\varphi = 0$, dimensions, orthogonality, "Check against the official key"). |

### Engineering Mechanics: derivation boxes, first principles and the rigid body order

These rules apply to every Engineering Mechanics theory note, worked solution and bank item, and to the pages built from them. `tools/derivation.py` holds the syntax, the renderer and the gate; `assets/css/derivation-box.css` the style.

- **No calculation in prose (`no-inline-calc`).** Outside a derivation box, a paragraph or a list item only names things with atomic identifiers (`$m$`, `$\theta$`, `$\mathbf r_0^P$`, `$S_1$`). Inline maths there may not contain an equals sign, `\dot`, `\ddot`, `\times`, `\frac` (or `\dfrac`, `\tfrac`) or `\int`, and no display formula (`$$`) stands outside a box. Definitions of symbols, frames and data go in a table (table cells are not checked); every development goes in a box. The gate runs on the rendered page (`derivation.gate`) and fails the `--check` of the builders.
- **A derivation box** is the Obsidian callout below, rendered as `<div class="derivation-box">`. It is self-contained: a head with the title of the step, the law invoked and the official citation (written outside `$...$`, so `source_links.py` can link it: `Notes.pdf, Eq. X.Y`, `[Lecture N, Slide M]`, `Problems.pdf, p. N`); the development in `aligned`, one operation per row with its reason on the right; the result in `\boxed{}`; the SI check; and the physical meaning. Nothing of the development is written above the box.

  ```
  > [!derivation] Velocity of the particle
  > **Law:** definition of velocity; time derivative taken in $S_0$
  > **Source:** Notes.pdf, Eq. 2.6; [Lecture 1, Slide 14]
  >
  > $$\begin{aligned}
  > \mathbf v_0^P &= \frac{d}{dt}\left(R\,\mathbf e_r\right) \quad &\text{(definition of velocity)} \\
  > &= R\,\dot\theta\,\mathbf e_\theta \quad &\text{(chain rule; $R$ is constant)}
  > \end{aligned}$$
  >
  > $$\boxed{\mathbf v_0^P = R\,\dot\theta\,\mathbf e_\theta}$$
  >
  > **Units:** $[\mathrm{L}]\,[\mathrm{T^{-1}}] = [\mathrm{L\,T^{-1}}]$
  > **Meaning:** the velocity is tangent to the circle and grows with the radius.
  ```

  A box may also hold sentences, `- ` list items and a figure embed. `derivation.parse` rejects a box without title, **Law**, **Source** with a citation, **Units**, **Meaning**, a `$$` development or a `\boxed` result, and an `aligned` row without its `\text{(...)}` reason.
- **Always from first principles.** A solution or example never starts from a ready-made formula (the polar or cylindrical acceleration components, $m\omega^2 r_\perp$ in place of $\boldsymbol\omega\times(\boldsymbol\omega\times\mathbf r)$, a tabulated moment of inertia) and never refers to another problem for a result. The chain is always: position vector $\mathbf r_0^P$ → change of basis matrices (with $\det R = 1$ and $R R^T = I$ checked) and derivatives of the unit vectors, $\dot{\mathbf u}_i = \boldsymbol\omega\times\mathbf u_i$ → $\mathbf v_0^P$ → $\mathbf a_0^P$ → Newton and Euler ($\sum\mathbf F = m\,\mathbf a_0^G$, $\mathbf M_Q = \dot{\mathbf H}_{Q,0} + \mathbf v_0^Q\times\mathbf p_0$). A moment of inertia is set up as its integral, with the volume element and its Jacobian. Each problem uses only the tools of its own unit or of earlier units.
- **Figures.** Besides the figures of the next section: one 2D view per rotation ($\psi$, $\theta$, $\phi$) with ⊙/⊗, the angle marked between both pairs of axes and the $3\times 3$ matrix in the box beside it; meridian sections and fold-downs with the right triangles shaded and the hypotenuse, the adjacent leg (cosine) and the opposite leg (sine) labelled; and the free-body diagram with applied forces, reactions and inertia forces, exploded with the pairs $\pm\mathbf R$ in multibody problems.
- **Rigid body problems** (`Problems.pdf` section 2, ids `rb-01` to `rb-42`, `"structure": 4` in `tools/mech_problems.json`, pages `problemas/topic-{6,7,8}.html`) follow this order: `### Reference Frames, Bases and Degrees of Freedom` → `### Change of Basis, Position Vectors and Constraint Kinematics` → `### Center of Mass and Inertia Tensor` (Steiner explicit) → `### Linear Momentum, Angular Momentum and Kinetic Energy` → `### Free-Body Diagram and Equations of Motion` → `### Answers and Checks` (with "Check against the official key", or limiting cases when the problem has no key).
- **Simulator.** Every problem card carries the geometry simulator of `assets/js/mechanics-3d-sim.js` (see "Exercise simulators"), connected by a `> [!example] Interactive simulator` callout in its solution whose next line is `> sim: {"archetype": ..., "params": {...}, "defaults": {...}, "readouts": [...]}` (JSON on one line). The Solution Set notes hold many problems each, so the configuration sits in the problem's own section instead of the note frontmatter.

### Explanation standard: nothing is "obvious"

- Every sine or cosine names its right triangle: which side is adjacent, which is opposite and which is the hypotenuse.
- Every minus sign in a change of basis is explained with the right-hand rule, saying which axis points out of the paper (⊙) or into it (⊗) in the view used, e.g. why $\mathbf i_1 = \cos\Omega t\,\mathbf i - \sin\Omega t\,\mathbf k$.
- An angle measured from a vertical (or from any axis other than the usual polar axis) is related to standard polar coordinates, with the proof, e.g. $\varphi = \theta - \pi/2$ and $\cos(\theta - \pi/2) = \sin\theta$.
- Every derivative, product of matrices and vector product is written out before its result.

### Figures: one drawing per plane and per rotation

Wherever a solution has vectors, projections, triangles or a change of basis, it carries its own deduction figures (not only the figure of the statement):

1. **Plane of the moving frame or main plane:** origin $O$, geometric centres ($C$), the particle $P$, dimensioned projections in dashed lines (e.g. $a\sin\theta$, $a(1-\cos\theta)$), the moving basis in one colour (blue: $\mathbf i_1, \mathbf j_1$) and the intrinsic or auxiliary vectors in a contrasting one (orange or green: $\mathbf e_t, \mathbf e_n$, $\mathbf e_{QP}$).
2. **View along each rotation axis:** a clean 2D view that says whether the axis points out of the paper (⊙) or into it (⊗), with the fixed axes in grey, the rotated axes in colour, and the arc of the angle ($\Omega t$, $\theta$, $\varphi$) with its sense.
3. **Right triangles and fold-downs** wherever the geometry is not trivial, with the legs ($d$, $d\tan\theta$, $\rho\sin\theta$), the hypotenuse ($d/\cos\theta$, $\rho$) and auxiliary angles labelled.

Figures are SVG written by a figure module in `tools/figures/` (thin grey axes, thick unit vectors with clear arrowheads, dashed projections, key triangles with a light translucent fill, one colour code per problem). Each one is rendered and inspected before it is committed: no label ($\theta$, $\varphi$, $\mathbf i_1$, $\mathbf e_t$) may sit on a line or an arrow.

### Content integrity

- Never adjust data, rounding, or an intermediate step to match an official answer. If the computed result differs from the official key, keep the computed value and add a discrepancy callout (`> [!warning] Discrepancy with the official solution` in the vault, a note box on the web page).
- If the official solution itself is wrong, show the correction as an erratum with the check that proves it; mark readings of handwriting or figures as such.
- Mark anything beyond the course material as "extension"; do not present it as course content.
- Vault note names are English: `Concept - ...`, `Problem - ...`, `Problem Set - ...` (a topic's problem statements), `Solution Set - ...` (its solutions), `Topic N - ...`, `Formula Sheet - ...`, `<Subject> MOC`, and the generated prefixes `Source - ...` and `Sources Index - ...` (see `vault/07 - Sources/`), `Tool - ...`, `Agent - ...` and `Rules - ...` (see `vault/06 - Repository/`). Rename notes with `python tools/vault_rename.py map.json --apply`, which rewrites every wikilink.
- Do not write `\euro` (undefined in KaTeX); use `€` inside `\text{}`.

## Review protocols

### `review` (standard task gate, after any single problem, note, page, or fix)
1. KaTeX delimiters balanced (`$...$`, `$$...$$`), no raw LaTeX errors.
2. Back-links point to `../../../index.html`.
3. Content is 100% academic English.
4. YAML frontmatter complete in `vault/` notes.
5. Subject MOC and root `index.html` entries updated; no stray scratch files left in the repo.
6. A visible change has its "What's new" entry in `assets/data/updates.js` (English, plain words, newest first, no lab material).

### `ultrareview` (chapter, problem sheet, exam, or on request)
Run the `review-ultrareview` skill, which checks four dimensions:
1. **Algebra and calculus:** zero algebraic skips; every chain rule, differential, and Barrow substitution explicit (`problem-step-mentor`).
2. **Frames and dimensions:** $[{}_0 R_1]$ orthonormal; every term dimensionally homogeneous in SI.
3. **Sources:** strict verification against the official PDFs in `sources/` (`source-researcher`).
4. **Web and memory:** theme persistence (`localStorage('ae_theme')` via `assets/js/theme.js`), responsive layout, zero JS console errors, `render_check` clean (`web-qa-reviewer`).

Run the auditors read-only and in separate contexts (math, theory against sources, web and hygiene); fix findings only after re-verifying each one independently.

## Token economy and memory

1. **Prompt cache stability:** keep system instructions, agent definitions, and skill frontmatter static; do not inject timestamps or volatile metadata into prompt prefixes.
2. **Context shielding:** never dump source PDFs, logs, or directory trees into the chat. Use targeted reads, `ctx_search`, or sandboxed `ctx_execute` to extract only what is needed.
3. **Memory persistence (`claude-mem`):** record resolved questions, verified formulas, and established frames as short summaries (<100 tokens) so future sessions can recover them cheaply.
4. **Concise responses:** when files are created or changed on disk, do not repeat their contents in chat. Give a clickable link, a summary of the diff, and the key rationale.

- `python tools/fluids_da/build.py --check` does the same for the Fluid Mechanics Topic 6 (dimensional analysis) problem page, its figures and figure captions in the notes; `python tools/fluids_da/verify_dimensional_analysis.py` re-solves its exponent systems and numbers.

## Git

- Every agent commits its finished work and pushes it to `origin` when it closes a task, so nothing is left uncommitted. The `web_qa_reviewer` role runs the checks and does the `git status` and `git add` before that commit, and pushes to `origin/main` unless the session names another branch.
- Commit messages: `type(scope): summary` (e.g. `feat(fluids): ...`, `chore(maths): ...`).
- The working tree may contain unrelated uncommitted changes. Stage only the files relevant to the task.
- The vault is committed to Git so every team member shares the same notes. Obsidian workspace and cache files, and `graphify-out/`, are gitignored.
