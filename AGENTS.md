# AGENTS.md

Shared rules for every AI agent working in this repository (Claude Code and Gemini). Tool-specific instructions live in `CLAUDE.md` (Claude Code) and `GEMINI.md` (Gemini). Edit this file for anything that applies to both.

## Purpose

Study material for the 2nd year of the BSc in Aerospace Engineering at UC3M: an Obsidian vault, a static HTML study portal, and the official course material they are built from. Two goals, in order:
1. Theory explained in full detail for each topic, faithful to the official sources.
2. Every problem of each topic solved one by one, step by step, with no algebraic skips.

## Architecture

Content flows in one direction; each layer must agree with the one before it:

```
sources/cuatrimestre-1/   (official course material, ground truth)
  └─► vault/              (Obsidian notes)
        └─► subjects/     (static HTML pages)
              └─► index.html  (portal landing page)
```

Subject folder names differ per tree, by design (see `sources/README.md` for the source layout):

| Subject | `sources/cuatrimestre-1/` | `vault/` | `subjects/` |
| :--- | :--- | :--- | :--- |
| Fluid Mechanics | `01-fluid-mechanics/` | `01 - Fluid Mechanics/` | `fluid-mechanics/` |
| Aerospace Materials I | `02-aerospace-materials-1/` | `02 - Aerospace Materials I/` | `aerospace-materials-1/` |
| Engineering Mechanics | `03-engineering-mechanics/` | `03 - Engineering Mechanics/` | `engineering-mechanics/` |
| Advanced Maths | `04-advanced-maths/` | `04 - Advanced Maths/` | `advanced-maths/` |
| Business Management | `05-business-management/` | `05 - Business Management/` | `business-management/` |

- **`sources/cuatrimestre-1/<NN-subject>/`**: official course material, organised by unit (`unit-0N-*/`) and by type (`teoria/`, `slides/`, `problemas/`, `examenes/`, `laboratorios/`, `schedule/`). Never invent equations, data, or problem statements; extract them and cite document and page/slide. `sources/update_inventory.py` and `.ps1` regenerate the inventory.
- **`vault/`**: Obsidian vault (open `vault/` itself). Subject folders as above, a `00 - Indice Central` MOC (update it when adding notes), `Templates/` (concept, exam problem, formula summary), `attachments/`, `06 - Repository/` (notes on the tools, agents and rules of this repo) and `07 - Sources/` (one generated note per file under `sources/`, with its status and the notes that reference it; generated by `tools/build_source_notes.py`, never edited by hand). Notes need YAML frontmatter and `[[wikilinks]]`. Wikilinks with a folder prefix must use the vault folder names from the table.
- **`subjects/<subject>/{teoria,problemas,sources,exams}/`**: `teoria/` and `problemas/` hold one `index.html` plus `topic-N-*.html` pages; `sources/index.html` ("Theory & exercise PDFs": theory, slides and problem sheets by unit) and `exams/index.html` ("Exams": first, second, third partial and final, newest year first) are generated by `python tools/build_sources_pages.py` (never edit them by hand). Exams are classified from their file names, `SUBJECT_KIND_YEAR[_DETAILS].pdf` with KIND one of `FIRSTPARTIAL`, `SECONDPARTIAL`, `THIRDPARTIAL`, `FINALEXAM` and details such as `ORD`, `EXTRA`, `RETAKE`, `SOL`, `P1`, `G45`, `MT3`; name new exam files that way. Exams from other universities or degrees use KIND `OTHERUNI` (`SUBJECT_OTHERUNI_YEAR_INSTITUTION[_DETAILS]`), live in `examenes/other-universities/`, and are listed in their own section. The index badges for both pages and the hero's PDF total are audited (`badge-drift`). Copy the structure of a sibling page rather than starting from scratch. **Laboratory material is never published on the web**: there are no lab pages, links, or lab entries in `assets/data/sources.js`; lab files stay in `sources/` only.
- **`assets/`**: shared portal assets: `css/celestial-sky.css`, `css/study-surface.css` (flat, opaque reading background for subject pages), `css/tokens.css` (design tokens), `css/hub.css` (root `index.html` only), `js/celestial-sky.js` (animated sky, root `index.html` only), `js/theme.js`, `js/i18n.js`, `js/quotes.js`, `css/source-links.css` (style of the PDF deep links), `css/responsive.css` (phone-width safety net), `js/ask-ai.js` + `css/ask-ai.css` (Ask AI), `js/focus-lab.js` + `css/focus-lab.css` (Focus Lab study sound), `js/pomodoro.js` + `css/pomodoro.css` (study timer and session planner), `js/updates.js` + `css/updates.css` ("What's new" bell and panel), `js/sidebar.js` + `css/sidebar.css` (side menu), `js/pdf-export.js` + `css/print.css` (PDF buttons and A4 print layout), `pdf/` (generated PDFs), and `data/sources.js` (generated by `tools/sources_manifest.py`; do not edit by hand).
- **`tools/`**: quality gates, see Verification below.

### Mandatory pipeline: Obsidian first, web second

1. Extracted content (course PDFs, notes, problems) is structured in `vault/` first, using `vault/Templates/`, and linked from the subject MOC.
2. Only then is the web page written in `subjects/`, using the vault note as ground truth. No web page exists without its vault note.

## Language and units

- All study material, vault notes, solved problems, and portal pages are written in **English**. Repo docs and some folder names are Spanish.
- SI units throughout; include a dimensional check.

## Problem-solving standard

A worked problem reads as one continuous academic development that follows the order, methods and notation of the lecturer of its subject. No problem, extra problem, vault note, template, page or PDF shows "Phase 1", "First phase", "Phase 2", ..., "four phases" or "4-phase" as a heading, badge, label or sentence. (The internal CSS class `phase-block` stays: it is never shown, and `ask-ai.js`, `solution-close.js` and `print.css` rely on it.)

### Internal verification checklist (silent)

Agents run this checklist in their head on every solution before it is written and when they review one. It is never written into the solution:

1. Hypotheses, degrees of freedom, constraints and data with SI units are stated, and the reason for each principle is given before it is used.
2. Every frame and basis is defined; every change-of-basis matrix (e.g. $[{}_0 R_1]$) is checked ($\det R = 1$, $R R^T = I$).
3. The derivation has no algebraic skips and cites its source for each result ("Notes Eq. 2.6", "Slide 29", "Robinson Eq. 5.12"):
   - chain rule explicitly, e.g. $\frac{d}{dt}f(u(t)) = \frac{df}{du}\frac{du}{dt}$; product rule $\frac{d}{dt}(uv) = \dot{u}v + u\dot{v}$ and implicit differentiation where they apply;
   - for each integral: the antiderivative, the substitution with its differential $du = u'(t)\,dt$, and the limits substituted via Barrow's rule $[F]_{t_1}^{t_2} = F(t_2) - F(t_1)$;
   - never jump straight from a derivative or integral to its result.
4. Physical meaning, limiting cases, asymptotic behaviour and the SI dimensional check are present.

### Visible structure: the lecturer's order, per subject

| Subject | Sections of a solution, in this order |
| :--- | :--- |
| Engineering Mechanics | **Reference frames, bases and coordinates** (fixed frame $S_0$, moving frames $S_1, \dots$, bases $B_0, B_1$, intrinsic basis $\{\mathbf e_t, \mathbf e_n, \mathbf e_b\}$, degrees of freedom, constraints, parameter table) → **Change of basis and position vector** (geometric and trigonometric deduction of every basis change and of the position vector, built step by step, e.g. $\mathbf r_1^P = \overrightarrow{OC} + \overrightarrow{CP}$, with its figures) → **Kinematics** (velocities and accelerations: chain rule, product rule, angular velocities, composition of motions and Coriolis) → **Forces and equations of motion** (free-body diagram, applied and constraint forces and inertia forces projected in the chosen basis, equations of motion; left out when the problem has no dynamics) → **Answers and checks** (the explicit answer to every part of the statement, limiting cases such as $\theta = 0$ or $\varphi = 0$, dimensions, orthogonality, "Check against the official key"). |
| Advanced Maths | The procedure of the class notes (`Notes.pdf`) for the method at hand: classification of the equation → choice of method and change of variable or basis → step-by-step solution → back to the original variable → (systems) eigenvalues and eigenvectors, change of basis $Q = [\mathbf u \mid \mathbf w]$, canonical form and phase portrait → checks. |
| Fluid Mechanics | Hypotheses and data → coordinates, frame or control volume → the equations or balances of the course, surface by surface → solution → checks (limits, dimensions, official key). |
| Aerospace Materials I | Data → model (the formula of the slides, cited) → calculation → result and checks. Crystallography: unit cell → coordinates → intercepts → Miller indices. |
| Business Management | Data and classification of every operation → income statement (EBITDA → EBIT → EBT → net income) → balance sheet → cash reconciliation → check against the official key. |

### Explanation standard: nothing is "obvious"

- Every sine or cosine names its right triangle: which side is adjacent, which is opposite and which is the hypotenuse.
- Every minus sign in a change of basis is explained with the right-hand rule, saying which axis points out of the paper (⊙) or into it (⊗) in the view used, e.g. why $\mathbf i_1 = \cos\Omega t\,\mathbf i - \sin\Omega t\,\mathbf k$.
- An angle measured from a vertical (or from any axis other than the usual polar axis) is related to standard polar coordinates, with the proof, e.g. $\varphi = \theta - \pi/2$ and $\cos(\theta - \pi/2) = \sin\theta$.
- Every derivative, product of matrices and vector product is written out before its result.

### Figures: one drawing per plane and per rotation

Wherever a solution has vectors, projections, triangles or a change of basis, it carries its own deduction figures (not only the figure of the statement):

1. **Plane of the moving frame or main plane:** origin $O$, geometric centres ($C$), the particle $P$, dimensioned projections in dashed lines (e.g. $a\sin\theta$, $a(1-\cos\theta)$), the moving basis in one colour (blue: $\mathbf i_1, \mathbf j_1$) and the intrinsic or auxiliary vectors in a contrasting one (orange or green: $\mathbf e_t, \mathbf e_n$, $\mathbf e_{QP}$).
2. **View along each rotation axis:** a clean 2D view that says whether the axis points out of the paper (⊙) or into it (⊗), with the fixed axes in grey, the rotated axes in colour, and the arc of the angle ($\Omega t$, $\theta$, $\varphi$) with its sense.
3. **Right triangles and fold-downs** wherever the geometry is not trivial, with the legs ($d$, $d\tan\theta$, $\rho\sin\theta$), the hypotenuse ($d/\cos\theta$, $\rho$) and auxiliary angles labelled.

Figures are SVG written by a figure module in `tools/figures/` (thin grey axes, thick unit vectors with clear arrowheads, dashed projections, key triangles with a light translucent fill, one colour code per problem). Each one is rendered and inspected before it is committed: no label ($\theta$, $\varphi$, $\mathbf i_1$, $\mathbf e_t$) may sit on a line or an arrow.

### Content integrity

- Never adjust data, rounding, or an intermediate step to match an official answer. If the computed result differs from the official key, keep the computed value and add a discrepancy callout (`> [!warning] Discrepancy with the official solution` in the vault, a note box on the web page).
- If the official solution itself is wrong, show the correction as an erratum with the check that proves it; mark readings of handwriting or figures as such.
- Mark anything beyond the course material as "extension"; do not present it as course content.
- Vault note names are English: `Concept - ...`, `Problem - ...`, `Problem Set - ...` (a topic's problem statements), `Solution Set - ...` (its solutions), `Topic N - ...`, `Formula Sheet - ...`, `<Subject> MOC`, and the generated prefixes `Source - ...` and `Sources Index - ...` (see `vault/07 - Sources/`), `Tool - ...`, `Agent - ...` and `Rules - ...` (see `vault/06 - Repository/`). Rename notes with `python tools/vault_rename.py map.json --apply`, which rewrites every wikilink.
- Do not write `\euro` (undefined in KaTeX); use `€` inside `\text{}`.

## Review protocols

### `review` (standard task gate, after any single problem, note, page, or fix)
1. KaTeX delimiters balanced (`$...$`, `$$...$$`), no raw LaTeX errors.
2. Back-links point to `../../../index.html`.
3. Content is 100% academic English.
4. YAML frontmatter complete in `vault/` notes.
5. Subject MOC and root `index.html` entries updated; no stray scratch files left in the repo.
6. A visible change has its "What's new" entry in `assets/data/updates.js` (English, plain words, newest first, no lab material).

### `ultrareview` (chapter, problem sheet, exam, or on request)
Run the `review-ultrareview` skill, which checks four dimensions:
1. **Algebra and calculus:** zero algebraic skips; every chain rule, differential, and Barrow substitution explicit (`problem-step-mentor`).
2. **Frames and dimensions:** $[{}_0 R_1]$ orthonormal; every term dimensionally homogeneous in SI.
3. **Sources:** strict verification against the official PDFs in `sources/` (`source-researcher`).
4. **Web and memory:** theme persistence (`localStorage('ae_theme')` via `assets/js/theme.js`), responsive layout, zero JS console errors, `render_check` clean (`web-qa-reviewer`).

Run the auditors read-only and in separate contexts (math, theory against sources, web and hygiene); fix findings only after re-verifying each one independently.

## Token economy and memory

1. **Prompt cache stability:** keep system instructions, agent definitions, and skill frontmatter static; do not inject timestamps or volatile metadata into prompt prefixes.
2. **Context shielding:** never dump source PDFs, logs, or directory trees into the chat. Use targeted reads, `ctx_search`, or sandboxed `ctx_execute` to extract only what is needed.
3. **Memory persistence (`claude-mem`):** record resolved questions, verified formulas, and established frames as short summaries (<100 tokens) so future sessions can recover them cheaply.
4. **Concise responses:** when files are created or changed on disk, do not repeat their contents in chat. Give a clickable link, a summary of the diff, and the key rationale.

## Verification tools

From the repository root (pure-stdlib Python 3, no installs):
- `python tools/vault_lint.py` lints `vault/` (`--fix` applies safe fixes).
- `python tools/audit_portal.py` gates `index.html` and `subjects/**/*.html`.
- `python tools/build_nav.py --check` fails if `assets/data/nav.js` is stale or `tools/nav.json` and the pages on disk disagree (run without `--check` to regenerate).
- `python tools/sources_manifest.py --check` fails if `assets/data/sources.js` is stale; `python tools/build_sources_pages.py --check` does the same for the `subjects/<slug>/sources/index.html` pages (run without `--check` to regenerate).
- `python tools/build_topic_pages.py --check` fails if a generated theory page or its figures no longer match the vault note.
- `python tools/build_problem_pages.py --check` fails if a Business Management Topic 3 problem page no longer matches its vault notes.
- `python tools/build_mech_problems.py --check` fails if an Engineering Mechanics official problem page (`problemas/topic-1..5.html`, 51 problems) no longer matches its vault notes (`Problem Set - Topic N`, `Solution Set - Topic N`) and `tools/mech_problems.json`, or if a solution does not follow its structure version.
- `python tools/fluids_ns/build.py --check` fails if the Fluid Mechanics Topic 4 problem page, its notes or its lists (source links, MOC, `tools/nav.json`, problems index card, portal counters) are stale.
- `python tools/source_links.py --check` fails if any page's PDF deep links are stale; `audit_portal` also fails on a problem card without its "Original statement" link (`missing-source-link`).
- `python tools/build_pdfs.py --check` fails if a PDF in `assets/pdf/` is missing, stale or orphaned (no browser needed; run without `--check` to print them, which needs Edge/Chrome).
- `python tools/render_check.py <pages>` (or `--all`) renders pages in headless Edge/Chrome with the real KaTeX and fails on any KaTeX error or leftover `$$`. `audit_portal`'s delimiter check does not catch undefined macros; this does.
- `python tools/vault_rename.py map.json [--apply]` renames vault notes and rewrites wikilinks (dry run by default).
- `python tools/build_source_notes.py --check` fails if a note in `vault/07 - Sources/` is missing, stale or orphaned; run without `--check` to regenerate them and their subject indexes.
- `python -m unittest discover -s tools/tests` runs the test suite.

A task is closed only when `vault_lint` and `audit_portal` report 0 errors, `render_check` is clean on every page you edited, the PDFs are rebuilt (`build_pdfs --check`), the tests pass and, if users can see the change, `assets/data/updates.js` has its entry.

## Git

- Every agent commits its finished work and pushes it to `origin` when it closes a task, so nothing is left uncommitted. The `web_qa_reviewer` role runs the checks and does the `git status` and `git add` before that commit, and pushes to `origin/main` unless the session names another branch.
- Commit messages: `type(scope): summary` (e.g. `feat(fluids): ...`, `chore(maths): ...`).
- The working tree may contain unrelated uncommitted changes. Stage only the files relevant to the task.
- The vault is committed to Git so every team member shares the same notes. Obsidian workspace and cache files, and `graphify-out/`, are gitignored.
